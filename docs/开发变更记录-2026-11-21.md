## 2. 架构新增：Multi-Loader 工程骨架

### [功能新增] 新建 `multiloader/` 多模块工程
- **新增目录/文件**：
  - `multiloader/settings.gradle`：插件仓库管理 + `include 'common','forge','neoforge'`
  - `multiloader/build.gradle`：根项目统一插件、仓库、子模块通用配置
  - `multiloader/gradle.properties`：JDK25 路径、JVM 参数、版本号、模组元数据
  - `multiloader/common/`、`multiloader/forge/`、`multiloader/neoforge/`（各含 `build.gradle` 与 `src/`）
- **模块职责**：
  - `common`：仅编译于原版 `minecraft` jar，**不允许出现任何加载器 API**；承载注册、业务逻辑、网络 payload、客户端渲染等共享代码。
  - `forge` / `neoforge`：各加载器专属实现（入口、平台抽象、事件桥接、网络通道、配置、客户端初始化），依赖 `common`。
- **跨加载器抽象**：自研 `platform/` 接口（`ModPlatform` / `Registrar` / `RegistryEntry` / `Platform` / `Ids` / `MenuFactory`），不引入 Architectury API 运行时前置，仅使用 Loom 工具链。
- **预期效果**：根目录一次 `gradlew build` 顺序编译三模块，在 `forge/build/libs` 与 `neoforge/build/libs` 各产出对应模组 jar。

## 3. 配置调整

### [配置] 新增 NeoForged ForgeCDN 镜像源（关键修复）
- **文件**：`multiloader/settings.gradle`、`multiloader/build.gradle`
- **修改**：在仓库列表中新增
  ```groovy
  maven { name = 'NeoForged'; url = 'https://neoforged.forgecdn.net/releases' }
  ```
  并在 `settings.gradle` 的 `pluginManagement` 与根 `build.gradle` 的 `allprojects.repositories` 中同步声明。
- **原因**：NeoForge userdev 的 `config.json` 依赖 `net.neoforged:neoform:26.2-2@zip`，该制品仅存在于 `maven.neoforged.net`，而该主机在当前网络下 443 端口不可达（DNS 解析至 CDN77 真实 IP 后仍连接超时）；bmclapi 旧域镜像不含 `neoform` 目录。
- **解决方案**：通过 WebSearch 发现 NeoForged 官方 Maven 的 ForgeCDN 接入点 `neoforged.forgecdn.net`，实测 `neoform-26.2-2.zip`（约 94 KB）可正常下载（HTTP 200）。
- **预期效果**：NeoForge 侧 Loom 配置阶段可解析 `mcp` 配置依赖，进入合并 / 补丁 / 编译管线。

### [配置] Gradle 子模块通用配置
- **文件**：`multiloader/build.gradle`
- **修改**：在 `subprojects` 块中提前
  ```groovy
  if (name == 'forge' || name == 'neoforge') { ext.set('loom.platform', name) }
  ```
  并统一 `java` 插件、Java 25 工具链、UTF-8 编译编码。
- **原因**：Loom 通过项目属性 `loom.platform` 决定当前模块应用哪套加载器管线；需在插件 apply 前设置。
- **预期效果**：Forge 模块生成 `forge` 配置、NeoForge 模块生成 `neoForge` 配置，分别解析对应 userdev。

### [配置] 仓库可达性治理
- 保留：`maven.architectury.dev`、`maven.fabricmc.net`、`maven.minecraftforge.net`、`https://bmclapi.bangbang93.com/maven`（旧域，含 neoforge userdev/universal）、Maven Central。
- 弃用：`bmclapi2.bangbang93.com`（302 重定向至 `cmcc.mirrors.ustc.edu.cn`，连接被拒）。

## 4. common 模块：清除加载器依赖（Bug 修复 / 兼容性）

> 目标：common 仅编译于原版 jar，凡 Forge 专有（`getPistonPushReaction`、`BlockEntity.onLoad`、`ForgeRegistries`、`@EventBusSubscriber`、`ForgeLayeredDraw` 等）API 一律移出，改为加载器无关实现。

### [Bug 修复] `ModConfigSpecHolder` 去 ForgeConfigSpec
- **文件**：`multiloader/common/.../ModConfigSpecHolder.java`
- **修改**：移除 `ForgeConfigSpec` 构建逻辑与 `@SubscribeEvent`；保留 `PistonBehavior` 枚举与全部静态字段默认值；新增 `apply(...)` 集中写入方法。
- **原因**：配置项读取是加载器专属 API，common 不应依赖。
- **预期效果**：各加载器模块在自己的配置类中读取后调用 `ModConfigSpecHolder.apply(...)`，common 只读字段。

### [Bug 修复] `PetrificationMod` 改为公共引导入口
- **文件**：`multiloader/common/.../PetrificationMod.java`
- **修改**：移除 `@Mod` 注解与 `FMLJavaModLoadingContext` 构造；新增 `bootstrap()`，在 `Platform.install()` 之后统一绑定全部注册器。
- **预期效果**：加载器入口先安装平台实现，再调用 `PetrificationMod.bootstrap()` 完成注册。

### [Bug 修复] `ModNetwork` 改为加载器门面
- **文件**：`multiloader/common/.../network/ModNetwork.java`
- **修改**：移除 Forge `Channel`/`ChannelBuilder`/`PacketDistributor`；改为 `Backend` 接口（`sendToServer` / `sendToClient`）+ 静态 `install()`。
- **预期效果**：加载器模块各自实现网络通道并注入，common 通过 `ModNetwork.sendToServer/sendToClient` 发包。

### [Bug 修复] `ClientSetup` 改为加载器无关
- **文件**：`multiloader/common/.../client/ClientSetup.java`
- **修改**：
  - HUD 快捷栏隐藏逻辑改为**整体反射**，通过 `installHudLayerClass(Class<?>)` 注入加载器的层类（Forge=`ForgeLayeredDraw`，NeoForge 对应实现），`ensureHudHotbarHiddenOnCoreGui()` 无参调用。
  - `getChild` / `addConditionTo` / `resolveLayers` / `bakedLayers` 均经反射访问；方法查找失败时回退到父类。
  - 保留 `registerSpecialItemRenderer()`（反射注册雕像物品特殊渲染器）与雕像颜色源辅助方法。
- **原因**：Forge 的 `ForgeLayeredDraw` 与 NeoForge 的对应类包名不同但成员同名，整体反射可同时兼容两侧且 graceful 失败。

### [Bug 修复] `ForgeRegistries.ENTITY_TYPES` → `BuiltInRegistries.ENTITY_TYPE`
- **文件**：`multiloader/common/.../util/MaterializationHelper.java`、`multiloader/common/.../block/PetrificationCoreBlockEntity.java`
- **修改**：将所有 `ForgeRegistries.ENTITY_TYPES.getKey(...)` 替换为 `BuiltInRegistries.ENTITY_TYPE.getKey(...)`，移除对应 import。
- **原因**：`BuiltInRegistries` 是原版 API，加载器无关。

### [Bug 修复] `StructureCompressionHelper` 移除事件注解
- **文件**：`multiloader/common/.../util/StructureCompressionHelper.java`
- **修改**：移除 `@Mod.EventBusSubscriber`、`@SubscribeEvent`、`TickEvent` 导入；`onLevelTick(TickEvent...)` 改为 `onLevelTick(ServerLevel)` 纯方法。
- **预期效果**：由加载器的 tick 事件转发调用。

### [Bug 修复] 移除 `getPistonPushReaction` 覆写，改为运行时处理
- **文件**：
  - `common/.../block/MiniStructureBlock.java`、`PetrificationCoreBlock.java`、`RestorationBlock.java`、`StatueBlock.java`（删除覆写）
  - `common/.../registry/ModBlocks.java`（4 个方块属性追加 `.pushReaction(PushReaction.PUSH_ONLY)`）
  - `common/.../util/PistonMoveData.java`（重写 `onPistonPre`）
- **修改**：
  - 原版无 `Block.getPistonPushReaction(BlockState)`（Forge 专有），删除 4 处覆写。
  - `PistonMoveData.onPistonPre` 签名改为 `(ServerLevel, BlockPos, Direction, boolean retracting, PistonStructureResolver) -> boolean`，返回 `true` 表示加载器应取消事件。
  - 运行时按配置处理：`BLOCK` → 取消；`MOVE` → 收回（拉回）时取消、推出时保存 BE 数据；`DROP` → 掉落容器内容 + `Block.dropResources` 销毁方块 + 取消。
  - 新增 `containsTracked` / `destroyBlocks` 辅助；`ModEventHandlers.onPistonPre` 同步签名。
- **预期效果**：活塞三态行为在加载器无关层完整保留，不依赖 Forge 专有覆写。

### [Bug 修复] 移除 `BlockEntity.onLoad()` 覆写
- **文件**：4 个方块实体（`MiniStructureBlockEntity` / `PetrificationCoreBlockEntity` / `RestorationBlockEntity` / `StatueBlockEntity`）+ `PistonMoveData.java`
- **修改**：删除各 BE 的 `onLoad()`（含 `PistonMoveData.restoreIfMoved` 调用），并删除 `PistonMoveData.restoreIfMoved` 方法。
- **原因**：`BlockEntity.onLoad()` 是 Forge 注入方法，原版不存在；活塞数据恢复本就由 `onLevelTick` 在后续 tick 对最终存活 BE 执行，`onLoad` 仅做校验/日志，可安全移除。
- **预期效果**：common 可在原版 jar 下编译；活塞 MOVE 数据恢复逻辑不变。

### [Bug 修复] `ModCreativeTabs` 加载器无关化
- **文件**：`multiloader/common/.../registry/ModCreativeTabs.java`
- **修改**：
  - 原版 `CreativeModeTab.Output` / `TabVisibility` 为 `protected` 内部类型，common 无法直接书写 `displayItems` lambda。
  - 改为：`PETRIFICATION_TAB` 由加载器通过 `registerTab(Supplier<CreativeModeTab>)` 注入构建好的标签页；条目内容统一由 `fillTabContents(Consumer<ItemStack>)` 提供。
  - 原版 `CreativeModeTabs.*` 常量为 private，改用自建 `ResourceKey`（`minecraft:building_blocks` 等）用于 `fillVanillaTab` 比较。
  - 修复 `ItemLike` import 路径（`net.minecraft.world.level.ItemLike`，非 `world.item`）。
- **预期效果**：物品清单只在 common 维护一份，两加载器各自构建标签页壳。

### [Bug 修复] `ModPotions` 泛型 Holder 上转型
- **文件**：`multiloader/common/.../registry/ModPotions.java`
- **修改**：`MobEffectInstance` 要求 `Holder<MobEffect>`，而注册项持有 `Holder<MaterializationEffect>`；新增 `asEffectHolder` 做安全上转型。
- **原因**：泛型不变性导致直接传参编译失败。

### [Bug 修复] `CoreSetWhitelistPayload` 恢复服务端校验
- **文件**：`multiloader/common/.../network/CoreSetWhitelistPayload.java`
- **修改**：载荷改回 `List<Identifier>`（非 String），`handle` 中用 `BuiltInRegistries.ENTITY_TYPE.containsKey` 校验、去重、上限 32 后写入。
- **原因**：此前改写时丢失了原版的服务端实体类型校验，且与 `core.setWhitelist(Set<Identifier>)` 类型不匹配。

## 6. 过程中遇到的问题与解决方案

### 问题 1：`Could not find net.neoforged:neoform:26.2-2`（阻塞）
- **现象**：NeoForge 配置阶段解析 `mcp` 配置失败，多镜像（bmclapi 旧域、bmclapi2、repo1、阿里云、maven.neoforged.net）均 404 / 不可达。
- **根因**：`neoform` 制品仅发布在 `maven.neoforged.net`，该主机在当前网络不可达。
- **解决**：WebSearch 发现 `neoforged.forgecdn.net`（NeoForged 官方 Maven 的 ForgeCDN 接入点）可用，新增为仓库源后解决。
- **注意事项**：`maven.neoforged.net` 与 `neoforged.forgecdn.net` 实为同一仓库的不同接入点，后者 CDN 可达性更好，应优先使用。

### 问题 2：Loom 缓存锁被 IDE 守护进程占用
- **现象**：`"Lock for cache=...fabric-loom ... held by pid '20164'"`，等待 60s 超时。占用者是 IDE（nbcode64）启动的 Gradle daemon。
- **解决**：`.\gradlew.bat --stop` 停止所有 daemon，删除 `D:\gradle\.gradle\caches\fabric-loom\*.lock`，重试。
- **注意事项**：
  - 不要强杀 Gradle 进程，会导致 `ACQUIRED_PREVIOUS_OWNER_MISSING → rebuilding loom cache`（可恢复但浪费时间）。
  - 避免同时跑两个 `gradlew`；IDE 语言服务可能触发额外 Gradle 构建，必要时用 `--no-daemon`。
  - 每次编译加 `--no-build-cache` 排除缓存干扰。

### 问题 3：common 编译报 26 个"找不到符号 / 不会覆盖超类型方法"
- **现象**：common 仅编译于原版 jar，Forge 专有 API（`getPistonPushReaction`、`onLoad`、`ForgeRegistries`、`CreativeModeTab.Output` 可见性等）全部报错。
- **解决**：按上文第 4 节逐项改写，通过 `javap` 反编译原版 `minecraft-merged.jar` 确认原版 API 真实签名与可见性后再改。
- **注意事项**：MC 26.2 原版 jar 已确认**未混淆**（真实类名），故 `loom-no-remap` 无需 mappings；但 Forge/NeoForge 注入的方法在原版 jar 中不存在，common 绝不能引用。

### 问题 4：bmclapi2 重定向失败
- **现象**：`https://bmclapi2.bangbang93.com/...` 302 至 `cmcc.mirrors.ustc.edu.cn`，连接被拒；`download.mocdn.net` 返回 403。
- **解决**：改用 bmclapi 旧域 `https://bmclapi.bangbang93.com/maven`（含 neoforge userdev/universal）。
